# Кандидатогенерация для поиска услуг Avito (Recall@50)

Для каждого поискового запроса решение отбирает до 50 объявлений из корпуса
`benchmark_items.parquet`. Итоговый файл — `answer.csv` (`query_id,answer`).

**Официальный результат: Recall@50 = 0.8215** (4 попытки из 7).

| Попытка | Что изменилось | Recall@50 |
|---|---|---|
| 1 | поиск внутри локации запроса, BM25 + BERT | 0.7399 |
| 2 | + радиус 100 км для запросов без объявлений своей локации | 0.7783 |
| 3 | BERT переобучен с негативами из той же локации | 0.8144 |
| 4 | BERT дообучен на 60 000 новых пар | **0.8215** |

## 1. Какие данные и признаки использованы и почему

**Данные.** `train.parquet` — обучение нейросети (пары «запрос → выбранное объявление») и
вычисление центров локаций. `benchmark_items.parquet` — корпус, по которому строится
BM25-индекс и из которого берутся hard negatives (используются только тексты объявлений).
`benchmark_queries.parquet` — запросы, для которых готовится ответ. Разметка бенчмарка
и идентификаторы `query_id` не использовались.

**Использованные признаки:**

| Признак | Зачем |
|---|---|
| `search_query`, `search_infm_params_text`, `search_category` | текст запроса для BM25 и нейросети |
| заголовок, описание, `item_infm_params_text`, категория и подкатегория объявления | текст объявления для BM25 и нейросети |
| `search_location_id`, `item_location_id` | **главный сигнал**: у 83.1% выбранных объявлений в train локация совпадает с локацией запроса |
| `item_latitude`, `item_longitude` | для запросов без объявлений своей локации: у 98.3% выбранных объявлений расстояние до центра локации запроса не больше 100 км |

**Проверены и отброшены:**

| Признак | Почему отброшен |
|---|---|
| рейтинг, число отзывов | перцентиль выбранного объявления по числу отзывов ≈ 0.49, то есть выбор от него не зависит; в ранжировании снижает Recall |
| цена | значения `-1` и `999999999999`, заметная часть записей — заглушки |
| скрытый телефон, запрет сообщений | у выбранных встречаются чуть реже (12.1% против 15.6%), но фильтр удаляет 18% нужных объявлений |
| флаг доставки | в train всего 12 строк с единицей |
| фильтры запроса («Вид услуги …») | выполняются на выбранных объявлениях в 97.7% случаев, но как жёсткое условие Recall не улучшили |

## 2. Какие модели и алгоритмы применены

Гибридная кандидатогенерация по мотивам статьи *Semantic Retrieval at Walmart*
(arXiv:2412.04637): лексический и нейросетевой источники, объединённые через RRF.

```
запрос ──► локация запроса ──► объявления этой локации (~1600 в среднем)
              │                        │
              │                 ┌──────┴───────┐
              │            BM25 (лексика)   BERT bi-encoder (смысл)
              │                 └──► RRF ◄─────┘ ──► top-50
              │
              └─ если в корпусе нет объявлений этой локации (17% запросов):
                 объявления в радиусе 100 км от «центра» локации, тот же поиск
```

1. **Текст.** Запрос: `search_query [SEP] search_infm_params_text [SEP] категория`.
   Объявление: заголовок, описание, параметры, категория, подкатегория, через `[SEP]`.
2. **Географический фильтр.** Кандидаты ищутся только среди объявлений локации запроса.
3. **BM25** (`bm25_index.py`) — собственная реализация на `scipy.sparse`: насыщенный
   TF × IDF считается один раз как разреженная матрица, скор запроса — произведение матрицы
   на бинарный вектор запроса. Токенизация — регулярка по буквам и цифрам, небольшой
   список стоп-слов.
4. **Bi-encoder** (`bert_two_tower.py`) — `cointegrated/rubert-tiny2` (открытая модель
   Hugging Face Hub, работает локально), mean pooling, проекция до 128 измерений,
   L2-нормализация, один общий энкодер для запроса и объявления. Обучение — InfoNCE
   (temperature 0.05) с in-batch негативами и 4 hard negatives на пример. Hard negatives —
   случайные 4 из BM25-топ-30 **внутри локации запроса**. Два этапа: 40 000 пар × 5 эпох
   (lr 2e-5), затем 60 000 новых пар × 3 эпохи (lr 1e-5).
5. **Запросы без объявлений своей локации** (427 из 2452). «Центр» локации — медиана
   координат объявлений, выбранных при поиске из неё в train. Поиск среди объявлений
   корпуса в радиусе 100 км (минимум 200 ближайших).
6. **Слияние.** Reciprocal Rank Fusion (`k=60`, равные веса), по 100 кандидатов от BM25
   и от bi-encoder, итог — 50 лучших. Если кандидатов меньше 50, добор из глобального
   списка (в бенчмарке так добирались 8 запросов).

Внешние API не используются, всё воспроизводится локально на CPU.

## 3. Как проверялось качество до отправки

Локальная оценка на отложенной части train: 3000 запросов, корпус из 150 000 объявлений
(истинное объявление каждого запроса гарантированно в корпусе, остальное — случайные).
Метрика — доля запросов, у которых нужное объявление попало в топ-50. При сравнении моделей
исключались запросы, строки которых модель видела при обучении (10.6% выборки).

**Ограничение:** корпус локальной оценки собран из train, а с корпусом бенчмарка train
пересекается по объявлениям лишь на 9.6%. Поэтому локальные числа завышены и годятся для
сравнения вариантов между собой, но не для прогноза официальной цифры. Например,
локальный прирост от переобучения нейросети был +0.8 п.п., а официальный — +3.6 п.п.

| Вариант | Recall@50 локально |
|---|---|
| BM25 | 0.236 |
| BERT (обучение по всему корпусу, 7 эпох) | 0.165 |
| BM25 + BERT (RRF) | 0.238 |
| + фильтр по локации, гео как третий список | 0.645 |
| поиск только внутри локации запроса, BM25 + BERT | 0.831 |
| то же, на запросах со своей локацией (1500 запросов) | 0.901 |
| запросы без своей локации: только глобально → радиус 100 км | 0.344 → 0.716 |
| BERT с негативами из локации (этап 1), BM25 + BERT (1340 запросов) | 0.911 |
| + дообучение на 60 000 пар (этап 2), BM25 + BERT (1340 запросов) | 0.917 |

Каждая из четырёх официальных попыток соответствовала одному улучшению, подтверждённому
локально. Формат `answer.csv` проверялся функцией `validate_answer_df` (`fuse_and_export.py`):
все `query_id` присутствуют и не повторяются, не больше 50 `item_id` в строке, без повторов,
все `item_id` есть в корпусе.

## 4. Какие типы ошибок найдены и что с ними сделано

| Ошибка / наблюдение | Как выявлено | Что сделано |
|---|---|---|
| Текстовые модели не отличают объявления внутри категории: медиана ранга нужного объявления 339 из 150 000, 74% в топ-1000, но лишь 16% в топ-50 | распределение рангов истинных объявлений | географический фильтр, Recall 0.24 → 0.83 |
| 17% запросов не имеют объявлений своей локации в корпусе | анализ покрытия локаций (427 из 2452) | радиус 100 км: локально 0.34 → 0.72, официально +3.8 п.п. |
| Расхождение обучения и инференса: негативы искались по всему корпусу, а различать нужно внутри локации | loss падал, а Recall почти не менялся (0.160 → 0.165) | переобучение с негативами из той же локации, официально +3.6 п.п. |
| BM25 и bi-encoder ошибаются на разных запросах (опечатки, синонимы) | по отдельности 0.864 и 0.853, вместе 0.901 | оставлен гибрид через RRF |
| Утечка в локальной оценке: 10.6% eval-запросов были в обучении первой модели | сверка индексов строк | модели сравнивались только на запросах без утечки |
| Шаблонный мусор в описаниях и параметрах | просмотр примеров | проверены чистка текста, основы слов, разделение полей: выигрыша вне шума нет |

**Гипотезы, которые не подтвердились** (локально, внутри локации запроса, база ≈ 0.90):

| Идея | Результат |
|---|---|
| Рейтинг и число отзывов третьим списком в RRF | хуже базы при любом весе |
| Убрать объявления со скрытым телефоном или запретом сообщений | 0.90 → 0.79 |
| Чистка текста BM25 | 0.885–0.899 против 0.901 |
| Жёсткий фильтр по «Вид услуги» | 0.889 → 0.889, теряет 6.7% нужных |
| BM25 по основам слов | 0.907 против 0.901, в пределах шума |
| Слоты под соседние локации | +0.7 п.п., в пределах шума |
| Расстояние до центра третьим списком | +0.3 п.п., в пределах шума |
| Дедупликация одинаковых объявлений | 0.911 → 0.747 (у одинаковых заголовков разные исполнители) |
| Параметры BM25, перекос весов в RRF | шум или хуже равных весов |
| Радиус в виде «N ближайших объявлений» | хуже радиуса 100 км |

**Остаточные ошибки:** около 5% нужных объявлений лежат вне локации запроса и
возвращаются лишь частично; для запросов без своей локации локальный Recall ≈ 0.72
против ≈ 0.91 у остальных; внутри локации объявления почти неразличимы по тексту
(шаблонные описания у сотен исполнителей), потолок по локации 94.7%.

## Открытые модели и библиотеки

- `cointegrated/rubert-tiny2` (Hugging Face Hub): веса скачиваются один раз при первом
  запуске, дальше работа идёт из кэша без сети.
- `torch`, `transformers`, `scikit-learn`, `scipy`, `numpy`, `pandas`, `pyarrow`, `tqdm`.

## Воспроизведение

```bash
uv venv && source .venv/bin/activate
uv pip install -r requirements.txt
```

Файлы `train.parquet`, `benchmark_queries.parquet`, `benchmark_items.parquet` — в папке `data/`.
Дальше — ячейки `notebook.ipynb` по порядку:

1. импорты, загрузка данных, тексты и BM25-индекс по корпусу бенчмарка (~30 c);
2. индекс объявлений по локациям и центры локаций по train;
3. этап 1: 40 000 пар и hard negatives внутри локации (~30 мин), обучение 5 эпох (~1.5 ч);
4. этап 2: 60 000 новых пар и негативы (~45 мин), дообучение 3 эпохи (~1.3 ч);
5. эмбеддинги корпуса и запросов бенчмарка (~3 мин);
6. поиск внутри локации, радиус для запросов без своей локации, RRF, запись `answer.csv` (~2 мин).

Время указано для CPU (16 ГБ ОЗУ, без GPU). Модули: `text_utils.py`, `bm25_index.py`,
`bert_two_tower.py`, `ann_search.py`, `fuse_and_export.py`, `local_eval.py`. Фиксированы seed'ы
numpy; seed torch не фиксировался, поэтому повторное обучение может дать результат,
отличающийся в третьем знаке.
