# Кандидатогенерация для поиска услуг Avito (Recall@50)

Для каждого поискового запроса решение отбирает до 50 объявлений из корпуса
`benchmark_items.parquet`. Итоговый файл — `answer.csv` (`query_id,answer`).

**Официальный результат: Recall@50 = 0.8215** (4 попытки из 7).

| Попытка | Что изменилось | Recall@50 |
|---|---|---|
| 1 | поиск внутри локации запроса, BM25 + BERT (7 эпох, негативы по всему корпусу) | 0.7399 |
| 2 | + радиус 100 км для запросов без объявлений своей локации | 0.7783 |
| 3 | BERT переобучен с негативами из той же локации (40 000 пар, 5 эпох) | 0.8144 |
| 4 | BERT дообучен на 60 000 новых пар (3 эпохи) | **0.8215** |

## Идея решения

Гибридная схема по мотивам статьи *Semantic Retrieval at Walmart*
(arXiv:2412.04637): лексический и нейросетевой источники кандидатов,
объединённые через Reciprocal Rank Fusion. Главные отличия от статьи, давшие
основной прирост:

1. **Географический фильтр.** Пользователи почти всегда выбирают объявление в своей
   локации, а чисто текстовые модели этого сигнала не видят.
2. **Обучение на той же задаче, что и инференс.** Поиск идёт среди ~1600 похожих
   объявлений одной локации, поэтому hard negatives для обучения берутся оттуда же.

```
запрос ──► локация запроса ──► объявления этой локации (~1600 в среднем)
              │                        │
              │                 ┌──────┴───────┐
              │                 │              │
              │            BM25 (лексика)   BERT bi-encoder (смысл)
              │                 │              │
              │                 └──► RRF ◄─────┘ ──► top-50
              │
              └─ если в корпусе нет объявлений этой локации (17% запросов):
                 объявления в радиусе 100 км от «центра» локации, тот же поиск
```

### Шаги

1. **Текст.** Запрос: `search_query [SEP] search_infm_params_text [SEP] категория`.
   Объявление: заголовок, описание, параметры, категория, подкатегория, через `[SEP]`.
   Токенизация для BM25 — регулярка по буквам и цифрам, нижний регистр, небольшой список стоп-слов.
2. **BM25** (`bm25_index.py`) — собственная реализация на `scipy.sparse`: насыщенный
   TF × IDF считается один раз как разреженная матрица весов, скор запроса — произведение
   матрицы на бинарный вектор запроса. Без внешних BM25-библиотек.
3. **Bi-encoder** (`bert_two_tower.py`) — `cointegrated/rubert-tiny2`, mean pooling,
   линейная проекция до 128 измерений, L2-нормализация. Один общий энкодер для запроса и
   объявления. Обучение — InfoNCE (temperature 0.05) с in-batch негативами и 4 hard negatives
   на пример. Hard negatives — случайные 4 из BM25-топ-30 **внутри локации запроса** по корпусу
   бенчмарка (используются только тексты объявлений, разметка бенчмарка не используется).
   Обучение в два этапа, оба на строках train:
   - этап 1: 40 000 пар, 5 эпох, lr 2e-5, старт с `rubert-tiny2`;
   - этап 2: дообучение на 60 000 новых парах, 3 эпохи, lr 1e-5.
4. **Локация.** Кандидаты ищутся только среди объявлений с `item_location_id`,
   равным `search_location_id` запроса. В train это верно для 83.1% выбранных объявлений.
5. **Запросы без объявлений своей локации** (427 из 2452 в бенчмарке). «Центр» локации —
   медиана координат объявлений, выбранных при поиске из этой локации в train. Дальше поиск
   среди объявлений корпуса в радиусе 100 км от центра (минимум 200 ближайших). 98.3% выбранных
   объявлений в train лежат не дальше 100 км от центра локации запроса.
6. **Слияние.** RRF (`k=60`) по спискам BM25 и BERT с равными весами, по 100 кандидатов
   из каждого, итог — 50 лучших. Если кандидатов меньше 50, добор из глобального списка
   (в бенчмарке так добирались 8 запросов).

## Оценка качества

Локальная оценка — 3000 запросов из train, корпус из 150 000 объявлений train. Она
**оптимистичнее** официальной: в корпусе бенчмарка объявлений из train лишь 9.6%, а
центры локаций считались по train. Поэтому локальные числа годятся для сравнения
вариантов между собой, но не для прогноза официальной цифры. При сравнении моделей
исключались запросы, строки которых модель видела при обучении.

| Вариант | Recall@50 локально |
|---|---|
| BM25 | 0.236 |
| BERT (обучение по всему корпусу, 7 эпох) | 0.165 |
| BM25 + BERT (RRF) | 0.238 |
| + фильтр по локации, гео как третий список | 0.645 |
| поиск только внутри локации запроса, BM25 + BERT | 0.831 |
| то же, на запросах со своей локацией (1500 запросов) | 0.901 |
| запросы без своей локации: только глобально → радиус 100 км | 0.344 → 0.716 |
| BERT с негативами из локации (этап 1), BM25 + BERT (1340 запросов) | 0.911 |
| + дообучение на 60 000 пар (этап 2), BM25 + BERT (1340 запросов) | 0.917 |

Локальный прирост от переобучения BERT (+0.8 п.п.) оказался заметно меньше
официального (+3.6 п.п.).

## Что проверено и не помогло

Проверки на локальных данных внутри локации запроса (база ≈ 0.90).

| Идея | Результат |
|---|---|
| Рейтинг и число отзывов как третий список в RRF | хуже базы при любом весе |
| Убрать объявления со скрытым телефоном или запретом сообщений | 0.90 → 0.79 (теряются 18% нужных) |
| Чистка текста BM25 (вес заголовка, обрезка описания, параметры без повторов) | 0.885–0.899 против 0.901 |
| Жёсткий фильтр по «Вид услуги» из запроса | 0.889 → 0.889, теряет 6.7% нужных |
| BM25 по основам слов (обрезка токенов до 4–5 символов) | 0.907 против 0.901 у базы, в пределах шума; не вошло в финал |
| Слоты под соседние локации (`own45 + radius100`) | +0.7 п.п., в пределах шума |
| Расстояние до центра как третий список в RRF | +0.3 п.п., в пределах шума |
| Дедупликация одинаковых объявлений | 0.911 → 0.747 (одинаковые заголовки у разных исполнителей) |
| Параметры BM25 (`k1`, `b`) | разброс в пределах шума |
| Перекос весов в RRF, двойной вес нейросети | хуже равных весов |
| Радиус в виде «N ближайших объявлений» | хуже фиксированного радиуса 100 км |
| Старая модель как дополнительный источник | без изменений |

## Открытые модели и библиотеки

- `cointegrated/rubert-tiny2` (Hugging Face Hub) — предобученная русская BERT, дообучается локально.
  Веса скачиваются один раз при первом запуске, дальше работа идёт из кэша без сети.
- `torch`, `transformers`, `scikit-learn`, `scipy`, `numpy`, `pandas`, `pyarrow`, `tqdm`.
- Внешние API не используются. Идентификаторы `query_id` и хардкод под запросы не применяются.

## Воспроизведение

```bash
uv venv && source .venv/bin/activate
uv pip install -r requirements.txt
```

Файлы `train.parquet`, `benchmark_queries.parquet`, `benchmark_items.parquet` — в папке `data/`.
Дальше — ячейки `notebook.ipynb` по порядку:

1. импорты, загрузка данных, тексты и BM25-индекс по корпусу бенчмарка (~30 c);
2. индекс объявлений по локациям и центры локаций по train;
3. этап 1: выбор 40 000 пар и hard negatives внутри локации (~30 мин), обучение 5 эпох (~1.5 ч);
4. этап 2: 60 000 новых пар и негативы (~45 мин), дообучение 3 эпохи (~1.3 ч);
5. эмбеддинги корпуса и запросов бенчмарка (~3 мин);
6. поиск внутри локации, радиус для запросов без своей локации, RRF, запись `answer.csv` (~2 мин).

Время указано для CPU (16 ГБ ОЗУ, без GPU). Модули: `text_utils.py`, `bm25_index.py`,
`bert_two_tower.py`, `ann_search.py`, `fuse_and_export.py` (RRF и проверка формата ответа),
`local_eval.py` (локальная оценка). Фиксированы seed'ы numpy; seed torch не фиксировался,
поэтому повторное обучение может дать результат, отличающийся в третьем знаке.

## Ограничения

- Внутри локации объявления почти неразличимы по тексту (шаблонные описания у сотен
  исполнителей). Потолок по локации — 94.7% локально.
- Около 5% нужных объявлений лежат вне локации запроса, и их удаётся вернуть лишь частично.
- Для запросов без объявлений своей локации (17%) локальный Recall заметно ниже (0.72 против 0.91).
